# 图示优先

解释"东西之间的关系"时，先画再补一两句说明，不用长段落描述空间结构。
图只画下面五类形态，每类固定两版画法：**对话版**（默认）和**可贴版**（要转达给别人时）。

## 一、何时出哪一版

- 默认出**对话版**，画完不追问要不要可贴版。
- 用户的话里带了**去向**——发群里、发给同事、写进 issue / commit / PR 描述 / 周报 / 文档——就直接出**可贴版**，不出对话版。
- 用户说"给我可贴版 / 能贴的"，把上一张图按可贴版重画；说"要好看的"，按对话版重画。重画不重新分析。
- 两版不同时出。

可贴版存在的原因：飞书、企业微信等聊天软件用比例字体、折叠连续空格、不渲染 Markdown 表格，任何依赖跨行对齐的结构贴过去都会散。可贴版只用**逐行自含**的结构：任何一行删掉其他所有行后仍能独立读懂，不靠上一行的第 N 列。

## 二、五类形态目录

每类只有这两种画法，不发明第三种。对话版符号只用轻量框线 `─ │ ├ └ ┌ ┐ ┬ ┴ ▼ ──>`，不与 `+ - |` 混用。

### 层级 / 目录 / 模块划分

对话版（前缀树）：

```
core
├─ api
│  └─ request.ts
└─ store
views
```

可贴版：同上，前缀树本身逐行自含。飞书 / 企业微信是否保留行首 `├─ │` 未验证；验证不通过则改用缩进编号：

```
1. core
1.1 api
1.1.1 request.ts
1.2 store
2. views
```

### 调用链 / 数据流 / 请求生命周期

对话版（框 + 竖线 + 分叉）：

```
请求进来
   │
   ├─ 命中缓存 ──> 直接返回
   │
   └─ 未命中
        │
        ▼
   core/api ──> 后端 ──> 写缓存 ──> 返回
```

可贴版（单行箭头链，一条路一行，分叉多写一行）：

```
请求 -> 命中缓存 -> 直接返回
请求 -> 未命中 -> core/api -> 后端 -> 写缓存 -> 返回
```

### 状态流转 / 分支判断

对话版（框线状态图）：

```
┌──────┐  start  ┌─────────┐  done  ┌──────┐
│ idle │ ──────> │ running │ ─────> │ idle │
└──────┘         └─────────┘        └──────┘
                      │ fail
                      ▼
                 ┌─────────┐
                 │ failed  │
                 └─────────┘
```

可贴版（状态放方括号，转移放箭头里，一行一条）：

```
[idle] --start--> [running]
[running] --done--> [idle]
[running] --fail--> [failed]
```

### 方案对比 / 前后差异

对话版（左右并排两块）：

```
现状                          目标
AI 脑补 ──> 手绘字符画        AI 写小 DSL ──> 渲染器 ──> 字符画
 (每次不同、宽度失控)          (同输入必同输出)
```

可贴版（"标签: 值"成对行，不用表格）：

```
现状: AI 脑补手绘，每次不同、宽度失控
目标: AI 写 DSL 交渲染器，同输入必同输出
```

### 时序（谁先谁后、谁等谁）

对话版（泳道图）：

```
client        api          db
  │  请求      │            │
  │ ─────────> │  查询      │
  │            │ ─────────> │
  │            │ <───────── │
  │ <───────── │            │
```

可贴版（编号 + 箭头 + 冒号，一行一步）：

```
1. client -> api : 发起请求
2. api -> db     : 查询
3. db -> api     : 返回结果
4. api -> client : 响应
```

## 三、通用规格

- 宽度 ≤ 72 列，超了拆成两张图。
- 图里只放短标签（模块名、函数名、状态名），长解释放图外。
- 图下配 2–4 行"怎么读"，点出最关键的一条路径或一个边界。
- 不做装饰性 ASCII art（大标题、边框花纹、emoji 拼图）。
- 图的规模一屏以内；信息太多就裁到主干或拆图。

## 四、表格

对话版可用 Markdown 表格。可贴版把表格降成"每行一条"，字段用 `｜` 分隔，第一行不写表头分隔线：

```
路 A｜提示词规范｜无依赖｜脚本只能判错不能改对
路 B｜DSL 渲染｜多一个运行时｜复杂图效果差
路 C｜只合并规则｜零成本｜无法量到有没有变好
```

## 五、正文结构

图周围的文字同样用短行结构，不用整段散文描述代码细节：

- 键值：`标签: 值`，一行一条
- 步骤：`1.` `2.` 编号行，一行一步
- 定位：`路径 -> 作用`，例如 `core/api/request.ts -> 统一封装请求与重试`
- 一段最多 3 行；超过就拆成列表或图

## 六、给人看的 md 文档里用 mermaid

**判据**：这份 md 是给人读的（README、设计文档、架构说明、交付报告、评审材料、
排查记录），就用 ```mermaid 画关键关系；只给 AI 读的文档（规则、skill、
AGENTS.md、领域知识库）不画。

选型对照：

| 要表达的 | 图类型 |
|---|---|
| 模块/组件间依赖、数据流 | `flowchart` |
| 多方交互、请求响应顺序 | `sequenceDiagram` |
| 状态机、生命周期 | `stateDiagram-v2` |
| 数据表/实体关系 | `erDiagram` |
| 类型/继承结构 | `classDiagram` |
| 排期、阶段划分 | `gantt` |

约束：

- 一份文档里图不超过 5 张；每张图配一句"这张图在说什么"
- 节点标签含 `()` `:` `,` 等符号时必须加引号：`A["fetch(id)"]`
- 图只画主干路径，异常分支写在图下的文字里

## 七、不要画的时候别画

- 一两句话说得清的线性事实（"改了 3 个文件"）——直接说
- 只有两个节点一条边的关系——一句话比图快
- 代码注释里不塞大图；确需图解的复杂算法，最多 5 行示意
- 已经有图能复用时不重画，指向原图即可
