# 默认守则（新团队建团时预填）

建团第 3 步问 boss "有没有先立的守则"时，**不留空模板**——先把下面这些平台无关、放之各项目皆准的条目预填进 `.tvs-boss/rules.md` 的"通用守则（全队）"段，boss 再按需增删。这些是从长期实践里沉淀出的默认项，**不含任何具体项目名**（项目专属红线仍归"各项目附加红线"段，由 boss 现场补）。

## 预填内容

```markdown
## 通用守则（全队）
- 合并干线 / 向干线（test/dev/master 等）push 必须先经 boss 确认；功能分支 commit 跟验收走、push 跟阶段闸口走，由 leader 自动放行（节奏见 leader-protocol 第二节）
- 提交信息说清"为什么"
- **worktree 固定落点**：需要 worktree 时一律建在 `<项目根>/.worktree/<分支名>/`，项目 `.gitignore` 须含 `.worktree/`；需求交付后即 `git worktree remove` 清理，不留尸体
- **允许队友用全局 skill**：派活时 leader 主动告知可用全局 skill 并点名当下最相关的几个——合适的 skill 该用就用。
- **按任务难易选模型，别一律 opus**：haiku=纯机械零风险（改常量/跑命令/git/文档）；sonnet=正确性敏感与常规实现（SQL/接口字段/组件/CRUD，下限不低于 sonnet）；opus=高难度（架构/复杂推理/审查/棘手 bug/跨系统权衡）。
- **机械/低难度活不用 fork**（fork 继承 leader 的 opus 且无法降档）——改派低档角色（档位已烤进角色定义）；fork 只留给"需继承 leader 满上下文 + 高难度"的活。
- **派活先喂"记忆工程"**：派任何 agent 时，要求它开工前先读该项目的记忆工程——项目根 `CLAUDE.md` + `.claude/rules/*`；**项目有 `.memory/` 的，首要入口是 `.memory/记忆索引.md`（按索引路由查业务导航/红线）**；没有 `.memory/` 的老项目才退到 OMC 项目记忆（`project_memory_read`）/ wiki（`wiki_query`/`wiki_read`），且只作只读参考、与 `.memory` 冲突时以 `.memory` 为准。目的：提速、降 token、不重复推导已记录的东西。**例外：派工单标注【微任务】的机械微操作跳过本条**——直接执行并验证，预读对 10 秒的正事是 5 分钟的税。
- **一功能一分支，绝不为"动作"另起分支**：分支对应业务功能需求的开发单元，不是对应某个操作。开 MR、回灌、发版、改个展示 bug 这类动作，一律在该功能已有的开发分支上继续干，禁止为了单一操作新建分支。派活/规划前 leader 必须先查有没有对应功能的现成分支——有就直接用，只有"全新、与现有任何分支都不属同一功能"才允许建新分支。
- **干线分支（test/dev/master 等环境分支）禁止直接写代码**：任何修复/改动都在功能分支上做，再 merge 进干线；进生产走 MR。干线分支只接收 merge，不接收直接 authored 的 commit——含 revert、微调也不许直接提在干线上。
```
