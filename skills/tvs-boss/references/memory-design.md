# 团队记忆设计

团队记忆 = 团队根下 `.tvs-boss/` 里的几个 md，**由 leader 直接读写**（不需要中间脚本）。

## 铁律：只存慢变量，记忆必须有界

> **会随"干了多久"增长的 → 不存（那是项目自己的事）；只随"几个项目、几个守则、几个契约"变的 → 才存。**

- ❌ 不存：开发历史、踩过的坑、谁此刻在干什么、任务流水、预算。
  - "谁在哪条分支干到哪步" = 快变量，leader 用 `git` 现推，不落盘。
  - "这个项目怎么构建/测试/业务细节" = 项目知识，留在各项目自己的记忆工程 / codegraph，**记忆里最多放个指针**。
- ✅ 判据：文件量只随"当前摊子多大"波动，开发再久也不膨胀。**发现需要越存越多，就是混进了多余的东西。**

**铁律的机械化（不赌 leader 自觉）**：`rules.md` 软上限 80 行、`contracts.md` 软上限 120 行——超限时状态栏（status.mjs）直接亮 ⚠，boss 看见就会追问。写入前自问一句就够：
- 进 rules 前："这是必须遵守的硬规矩，还是一次事故的经过叙述 / 仓库 hook 里本来就写着的规范？"——后两者不进（事故只留一句结论；hook/CI 里的规范队员该现场读，抄进来必漂移）。
- 进 contracts 前："这是接口约定+版本号，还是任务状态（'待联调''分支未合''待 boss 定'）？"——状态类进 `work/` 或原生 Task，不进契约；接口全文档放项目 repo docs/，契约里只留端点+版本+一句差异摘要与指针。

## 三件套

### `.tvs-boss/projects.md` —— 项目注册表（含编制）
leader 动态建团、崩溃恢复的地基。每个纳管项目一段：

```markdown
## my-project
- path: /workspace/my-project
- repo: https://github.com/org/my-project
- 主分支: main
- 编制: dev×1
- 测试分支: test
- 预发布分支: staging
- 生产分支: master
```
> `主分支` 是项目固定属性（如某项目主线是 `develop` 而非 `main`），leader 判断"合主线"时认它。

#### 环境分支三件套（测试/预发布/生产）

`测试分支` / `预发布分支` / `生产分支` 是可选字段，记录该项目**部署环境**对应的分支名（不是开发流程里的"主分支"，两者常不同，如 shirehub 主分支是 `master` 但测试环境走 `test`）。leader 据此回答"这条功能分支合到哪了、离上线还差多远"，并在分支闸门/合线判断时认它。

**铁律：没有就是没有，不许猜。** 某个字段缺失（该项目还没理清测试/预发布/生产的分支映射，或某环境本就不存在）时**留空**——留空就是真实状态。**绝不**为了"看起来完整"去猜一个分支名填进去（猜错比欠缺更危险：会推出一个看似权威、实则错误的合线判断）。理清后再由 boss 拍板补上。

维护时机：建团第 3 步登记项目时，顺带问一句"这个项目的测试/预发布/生产分支分别是什么，不确定的留空即可"；日常运行中 boss 澄清了某条环境分支，leader 随手补进对应项目段。

### `.tvs-boss/rules.md` —— 守则（必须遵守的硬规矩）
分两段，几乎不变：

```markdown
## 通用守则（全队）
- 合并干线 / 向干线 push 必须先经 boss 确认；功能分支 commit/push 按闸口自动
- 提交信息说清"为什么"

## 各项目附加红线
- （按实际项目填写，如：某项目主线是 develop 而非 main）
```

### `.tvs-boss/contracts.md` —— 跨项目契约（仅多项目协作时）
存**当前**契约 + 版本号（不是变更史）：

```markdown
## shirehub ↔ way-community（v3）
- 接口约定：……
- 依赖方：way 按 v3 对齐
```

## 运行态暂存区 `work/`（不是记忆）

`.tvs-boss/work/<需求slug>/` 是任务过程产物（审查报告 / 拆解子任务图 / 分析文档）的**唯一落点**，由派工单【产出目录】字段下发。它是显式声明的运行态暂存区，**不受"记忆三件套"管辖，也不许冒充记忆**：需求交付即清（有长期价值的移入项目 repo 随分支 commit；团队级慢变量升华进 rules/contracts；其余整目录删除），细则见 `leader-protocol.md` 第十三节。

**`.tvs-boss/` 顶层白名单**：三件套（projects.md / rules.md / contracts.md）+ `work/`。出现白名单外的文件即违规产物，leader 按上面流程处置（旧版遗留的 `panel.cmd` / `panel.command` 直接删）。

## 与项目自身记忆的分工

```
团队记忆(.tvs-boss/)  ：项目注册表 / 守则 / 契约   —— leader 调度、恢复、建团用
项目记忆(各项目内部)   ：业务、代码风格、领域知识    —— 绑项目的角色用，不重复进团队记忆
git（活跃态）         ：谁在哪条分支干什么          —— 现推，不落盘
```
