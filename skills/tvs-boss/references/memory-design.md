# 团队记忆设计

团队记忆 = 团队根下 `.tvs-boss/` 里的几个 md，**由 leader 直接读写**（不需要中间脚本）。

## 铁律：只存慢变量，记忆必须有界

> **会随"干了多久"增长的 → 不存（那是项目自己的事）；只随"几个项目、几个守则、几个契约"变的 → 才存。**

- ❌ 不存：开发历史、踩过的坑、谁此刻在干什么、任务流水、预算。
  - "谁在哪条分支干到哪步" = 快变量，leader 用 `git` 现推，不落盘。
  - "这个项目怎么构建/测试/业务细节" = 项目知识，留在各项目自己的记忆工程 / codegraph，**记忆里最多放个指针**。
- ✅ 判据：文件量只随"当前摊子多大"波动，开发再久也不膨胀。**发现需要越存越多，就是混进了多余的东西。**

## 三件套

### `.tvs-boss/projects.md` —— 项目注册表（含编制）
leader 动态建团、崩溃恢复的地基。每个纳管项目一段：

```markdown
## crestrail
- path: E:/crestrail
- repo: http://mind-git.im30.lan/crestrail/crestrail/
- 主分支: main
- 编制: dev×1
```
> `主分支` 是项目固定属性（如某项目主线是 `shirehub` 而非 `main`），leader 判断"合主线"时认它。

### `.tvs-boss/rules.md` —— 守则（必须遵守的硬规矩）
分两段，几乎不变：

```markdown
## 通用守则（全队）
- push / 合并主线必须先经 boss 确认
- 提交信息说清"为什么"

## 各项目附加红线
- way-community-server-api：主线是 shirehub，别对 main
```

### `.tvs-boss/contracts.md` —— 跨项目契约（仅多项目协作时）
存**当前**契约 + 版本号（不是变更史）：

```markdown
## shirehub ↔ way-community（v3）
- 接口约定：……
- 依赖方：way 按 v3 对齐
```

## 与项目自身记忆的分工

```
团队记忆(.tvs-boss/)  ：项目注册表 / 守则 / 契约   —— leader 调度、恢复、建团用
项目记忆(各项目内部)   ：业务、代码风格、领域知识    —— 绑项目的角色用，不重复进团队记忆
git（活跃态）         ：谁在哪条分支干什么          —— 现推，不落盘
运行态 scratchpad     ：当前在岗 spawn 名单            —— live-agents.json，git 推不出故破例落临时文件，被覆盖、非记忆
```

> `live-agents.json` 是唯一的例外：它是"当前在岗"快照，给面板实时显示用；之所以落盘是因为 spawn 列表 git 推不出来。它会被 leader 不断覆盖、只反映此刻、不进记忆三件套——所以不违"记忆有界"。
