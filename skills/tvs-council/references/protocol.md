# 议会协议模板

主持人在各步直接套用。占位符用 `{}`。

## 落盘目录

```
~/.tvs-council/{YYYY-MM-DD}-{议题短名}/
├── 00-议题.md          发起人原话 + 议题陈述
├── 01-事实清单.md      全场连续编号，逐轮追加
├── 草案-v{n}.md        每版草案全文（v1 起），可回退
├── issues-{n}.md       第 n 轮四席回信原文 + 「书记」处置表
├── 状态表-{n}.md       第 n 轮下发的四席状态表
├── .material-{n}.md    第 n 轮席位材料（席位用 Read 读）
├── 裁决记录.md         发起人每次裁决原文，追加
└── 纪要.md             结束时写
```

议题短名取 2-6 个字，只用中文、字母、数字、连字符。目录在第 2 步发起人确认议题陈述后创建。`~` 指用户主目录，写入前展开为绝对路径。材料与回信只落文件，主持人不在对话里粘贴全文。

## 第 2 步：议题陈述

```
## 议题陈述

意图：{发起人要达成什么，一句话}
约束：{明确说过的限制；没有写"无"}
已知事实：{发起人给出的、可当事实用的信息}
发起人方案：{发起人已有的做法、倾向、想用的东西，原话保留；没有写"无"}
轮次上限：{发起人给的数字；没给写"不设，由发起人喊收尾"}
```

删除规则：只删对议会的要求（"别光附和我""多角度看看"）和情绪句。倾向句进"发起人方案"，不删。示例：

| 原话 | 处理 |
|---|---|
| 我打算把 A 换成 B，我基本想好了就用 B | 意图：A 的替代方案选择。已知事实：现状是 A。发起人方案：换成 B |
| 别光附和我 | 删 |
| 我觉得 X 更好 | 发起人方案：倾向 X |
| 上线时间是下月底 | 约束：下月底上线 |

发起人没提轮数时，改写后先问一句："最多陪跑几轮？"，答案写进轮次上限。"发起人方案"非"无"时即为草案 v0。改写后对发起人说：

```
议题陈述如上。确认后开会，或告诉我哪里改写错了。
```

## 第 3 步：事实清单

```
## 事实清单

### 本地现状
- #1 {事实}（来源：{文件路径 / git 引用 / codegraph 符号 / 约定或系统说明的名称}）

### 先人方案
- #2 {方案名}：解决 {什么}；已知局限 {什么}（来源：{链接}）
- 未找到时写"未找到成熟方案"，并附搜索用的关键词

### 外部权威
- #3 {事实}（来源：{链接或文献}）
```

编号全场连续。后续轮次补取证的条目追加在末尾，标"（第 n 轮后追加，因 ISSUE-x 待验证）"。无内容的分节写"无"。三节全无时整份写"事实清单为空"，仍然发给席位。

## 第 4 步：开路轮

无 v0，或 v0 只覆盖 §1 一节，第一批（同一条消息里两次 Agent 调用）：

```
Agent(name="council-sixu", subagent_type="general-purpose", prompt=
  通用段 + 「思绪」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单} +
  "\n\n请开路。")
Agent(name="council-jiagoushi", ...同上，换「架构师」专属段)
```

收齐后起「书记」：

```
Agent(name="council-shuji", subagent_type="general-purpose", prompt=
  「书记」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单} +
  {有 v0 时："\n\n## 发起人方案 v0\n" + 原文} +
  "\n\n## 「思绪」发言\n" + {原文} +
  "\n\n## 「架构师」发言\n" + {原文} +
  "\n\n请起草 v1。")
```

有 v0 且覆盖多节，直接起「书记」（不带两席发言）。

呈现给发起人：

```
## 草案 v1
{「书记」回信全文}
```

写 `草案-v1.md`，不停下，进第 5 步。

## 第 5 步：质询轮投递

先写状态表 `状态表-{n}.md`（首轮为空表），每席一段：

```
## 「{席位}」状态表（第 {n} 轮前）
| ISSUE | 针对 | 严重度 | 陈述原句 | 定案方式 | 处置状态 | 被驳回理由 / 推荐裁决 |
|---|---|---|---|---|---|---|
```

含本席历轮全部 issue。已关闭且其被驳回理由已被后续采纳覆盖的条目只保留编号、针对、处置状态三列。

再写材料 `.material-{n}.md`（四席读的完全相同，状态表四段全放，席位只看自己那段）：

```
## 草案 v{n}
{全文}

## 上一轮处置表
{原文；首轮写"首轮，无处置表"}

## 未关闭 issue 原文
{待裁决 / 待验证 / 上轮新暂定 的 issue 全字段原文；没有写"无"}

## 事实清单追加
{本轮新增条目；没有写"无"}

## 发起人裁决
{原文；没有则无此段}

## 发起人插话
{原文；没有则无此段}

## 四席状态表
{状态表-{n}.md 全文}

---
本场轮次上限 {N}，本轮第 {n} 轮。{末轮时改为："本轮为末轮：只收表态、反驳、撤回、升级，不接新 issue。"}
请对草案 v{n} 开 issue、反驳、表态、撤回或升级。
```

四席每轮新建（同一条消息里四次 Agent 调用，名字沿用）：

```
Agent(name="council-sixu", subagent_type="general-purpose", prompt=
  通用段 + 「思绪」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单全文} +
  "\n\n## 材料\n本轮材料在文件 " + {.material-n.md 绝对路径} + "，用 Read 工具读取这一个文件，只读它。本席状态表在文件"四席状态表"一节的「{席位}」段。")
Agent(name="council-jiagoushi", ...)
Agent(name="council-qiongchali", ...)
Agent(name="council-yonghu", ...)
```

某席只报"已完成"而没有回信正文时，用 SendMessage 让它把回信原文发回。回信不是 issue 格式时，让它按通用段的格式重发。

## 第 6 步：合并投递

四席回信收齐后写入 `issues-{n}.md`（原文），然后一次 SendMessage 给「书记」：

```
SendMessage(to="council-shuji", message=
  "第 {n} 轮四席回信在文件 " + {issues-n.md 绝对路径} + "，本轮材料在 " + {.material-n.md 绝对路径} + "，用 Read 读这两个文件。" +
  {有发起人裁决时："\n发起人裁决：\n" + 原文} +
  {有发起人插话时："\n发起人插话：\n" + 原文} +
  {有补取证时："\n事实清单追加：\n" + 新条目} +
  {末轮时："\n本轮为末轮。"} +
  "\n请合并，出草案 v{n+1}。过长分两条发。")
```

「书记」回信缺五段中任何一段，用 SendMessage 让它补发，不由主持人补。

## 第 7 步：停下

主持人核对：处置表每条"采纳"在 `草案-v{n+1}` 对应 §里确实改了；没改的列出编号，SendMessage 让「书记」补改并重发处置表，不由主持人改。核对通过后写 `草案-v{n+1}.md`，处置表追加进 `issues-{n}.md`。

主持人补取证：处置表每条"待验证"按其定案方式取证，追加 `01-事实清单.md`；取不到写"未取到"。

呈现给发起人：

```
## 第 {n} 轮

### 草案 v{n+1} 改动
{「书记」改动摘要原文}

### 处置表
{「书记」处置表原文}

### 待你裁决
{「书记」"待发起人裁决"一节原文（白话格式）；没有写"无"}

### 席位代裁的暂定项
- ISSUE-x：{一句}（你可推翻）
（没有写"无"）

收敛状态：{「书记」收敛状态原文}
草案全文见 ~/.tvs-council/{目录}/草案-v{n+1}.md
```

然后停下：

```
AskUserQuestion:
  question: "第 {n} 轮结束。下一步？"
  options:
    - 裁决        对待裁决项给答案，或推翻暂定项（待裁决与暂定都为空时不放此项）
    - 插话        我有话要说，说完再来一轮
    - 再来一轮    直接进下一轮
    - 拍板        我定了，出纪要
```

发起人选"裁决"或"插话"后，用纯文本等发起人输入。裁决原文追加进 `裁决记录.md`：

```
## 第 {n} 轮后
- ISSUE-x：{发起人原话}
```

收到后进入第 5 步（下一轮为末轮时进入第 8 步）。发起人在任何时候说"散会"，进入第 10 步，结论写"未拍板"。

## 第 8 步：末轮

触发：下一轮 = 轮次上限；或无上限时发起人说"收尾 / 打包"。按第 5 步投递，材料末尾标"本轮为末轮"。四席回信只含表态、反驳、撤回、升级。按第 6 步交「书记」并注明"本轮为末轮"。「书记」回信 = 终版草案 + 打包清单。

呈现给发起人：

```
## 末轮

### 终版草案改动
{改动摘要原文}

### 打包清单（逐条裁决，或只回复最后一行）
{「书记」打包清单原文，白话格式}
以上未逐条回复的按推荐执行。
```

然后停下：

```
AskUserQuestion:
  question: "末轮结束。怎么拍板？"
  options:
    - 逐条裁决    我逐条给答案
    - 按推荐执行  以上未逐条回复的按推荐执行，视为拍板
    - 散会        未拍板
```

## 第 9 步：拍板

- 逐条裁决 / 按推荐执行：裁决原文写 `裁决记录.md`，SendMessage 给「书记」出终版（未逐条回复的按推荐写入，标"发起人概括拍板"）。
- 散会：未裁项不进终版正文，只进 §6 标"待发起人"。

发起人在末轮之前任何一轮说"拍板"，以当前版为终版，待裁决与暂定项按第 8 步打包呈现一次再进本步。

## 第 10 步：纪要

```
# {议题短名}（{YYYY-MM-DD}）

## 结论
{拍板：发起人原话 ／ 概括拍板：按推荐执行 ／ 散会：未拍板，含 N 条未裁项}

## 最终草案
{终版草案全文}

## 决策记录
| ISSUE | 提出席位 | 严重度 | 最终处置 | 反驳 | 理由 |
|---|---|---|---|---|---|
（整场所有 issue，按席位与编号；处置含"席位代裁""发起人裁决""发起人概括拍板""待发起人"）

## 未决项
- {终版 §6 的条目；没有写"无"}

## 轮次
开路轮 {有/无}，质询轮 {n} 轮，末轮 {有/无}；收敛走势 open / 待裁决 / 暂定 / 待验证 逐轮：{…}。过程见同目录 草案-v*.md / issues-*.md / 状态表-*.md / 裁决记录.md。
```

未拍板时"结论"一节只写"未拍板，含 N 条未裁项"，不得出现主持人建议。
