# 议会协议模板

主持人在各步直接套用。占位符用 `{}`。

## 落盘目录

```
~/.tvs-council/{YYYY-MM-DD}-{议题短名}/
├── 00-议题.md          发起人原话 + 议题陈述
├── 01-事实清单.md
├── 草案-v{n}.md        每版草案全文（v1 起）
├── issues-{n}.md       第 n 轮四席回信原文 + 「书记」处置表
├── 裁决记录.md         发起人每次裁决原文，追加
└── 纪要.md             结束时写
```

议题短名取 2-6 个字，只用中文、字母、数字、连字符。目录在第 2 步发起人确认议题陈述后创建。`~` 指用户主目录，写入前展开为绝对路径。

## 第 2 步：议题陈述

```
## 议题陈述

意图：{发起人要达成什么，一句话}
约束：{明确说过的限制；没有写"无"}
已知事实：{发起人给出的、可当事实用的信息}
发起人方案：{发起人已有的做法、倾向、想用的东西，原话保留；没有写"无"}
```

删除规则：只删对议会的要求（"别光附和我""多角度看看"）和情绪句。倾向句进"发起人方案"，不删。示例：

| 原话 | 处理 |
|---|---|
| 我打算把 A 换成 B，我基本想好了就用 B | 意图：A 的替代方案选择。已知事实：现状是 A。发起人方案：换成 B |
| 别光附和我 | 删 |
| 我觉得 X 更好 | 发起人方案：倾向 X |
| 上线时间是下月底 | 约束：下月底上线 |

"发起人方案"非"无"时即为草案 v0。改写后对发起人说：

```
议题陈述如上。确认后开会，或告诉我哪里改写错了。
```

## 第 3 步：事实清单

```
## 事实清单

### 本地现状
- #1 {事实}（来源：{文件路径 / git 引用 / codegraph 符号 / 约定或系统说明的名称}）

### 先人方案
- #2 {方案名}：解决 {什么}；已知局限 {什么}（来源：{链接}）
- 未找到时写"未找到成熟方案"，并附搜索用的关键词

### 外部权威
- #3 {事实}（来源：{链接或文献}）
```

编号全清单连续。无内容的分节写"无"。三节全无时整份写"事实清单为空"，仍然发给席位。

## 第 4 步：开路轮

无 v0，第一批（同一条消息里两次 Agent 调用）：

```
Agent(name="council-sixu", subagent_type="general-purpose", prompt=
  通用段 + 「思绪」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单} +
  "\n\n请开路。")
Agent(name="council-jiagoushi", ...同上，换「架构师」专属段)
```

收齐后起「书记」：

```
Agent(name="council-shuji", subagent_type="general-purpose", prompt=
  「书记」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单} +
  "\n\n## 「思绪」发言\n" + {原文} +
  "\n\n## 「架构师」发言\n" + {原文} +
  "\n\n请起草 v1。")
```

有 v0，直接起「书记」：

```
Agent(name="council-shuji", subagent_type="general-purpose", prompt=
  「书记」专属段 +
  "\n\n## 议题陈述\n" + {陈述} +
  "\n\n## 事实清单\n" + {清单} +
  "\n\n请起草 v1。")
```

呈现给发起人：

```
## 草案 v1
{「书记」回信全文}
```

写 `草案-v1.md`，不停下，进第 5 步。

## 第 5 步：质询轮投递

材料正文（四席收到的完全相同）：

```
## 草案 v{n}
{全文}

## 上一轮处置表
{原文；首轮写"首轮，无处置表"}

## 发起人裁决
{原文；没有则无此段}

## 发起人插话
{原文；没有则无此段}

---
请对草案 v{n} 开 issue、撤回或升级本席被驳回的 issue、附议他席 issue。
```

首次出场的席位用 Agent 创建（prompt = 通用段 + 专属段 + 材料正文），已出场的用 SendMessage（message = 材料正文）。同一条消息里发完四席。

某席只报"已完成"而没有回信正文时，用 SendMessage 让它把回信原文发回。回信不是 issue 格式时，用 SendMessage 让它按通用段的格式重发。

## 第 6 步：合并投递

四席回信收齐后，一次 SendMessage 给「书记」：

```
SendMessage(to="council-shuji", message=
  "## 第 {n} 轮四席回信\n\n" +
  "### 「思绪」\n" + {原文} +
  "\n\n### 「架构师」\n" + {原文} +
  "\n\n### 「穷查理」\n" + {原文} +
  "\n\n### 「用户」\n" + {原文} +
  {有发起人裁决时："\n\n### 发起人裁决\n" + 原文} +
  {有发起人插话时："\n\n### 发起人插话\n" + 原文} +
  "\n\n请合并，出草案 v{n+1}。")
```

「书记」回信缺四段中任何一段，用 SendMessage 让它补发，不由主持人补。

## 第 7 步：停下

呈现给发起人：

```
## 第 {n} 轮

### 草案 v{n+1} 改动
{「书记」改动摘要原文}

### 处置表
{「书记」处置表原文}

### 待你裁决
- ISSUE-x（{提出席位}）：{处置表理由栏的一句话问题}
（没有则写"无"）

收敛状态：{「书记」收敛状态原文}
草案全文见 ~/.tvs-council/{目录}/草案-v{n+1}.md
```

写 `草案-v{n+1}.md`（「书记」草案全文）、`issues-{n}.md`（四席回信原文 + 处置表）。然后停下：

```
AskUserQuestion:
  question: "第 {n} 轮结束。下一步？"
  options:
    - 裁决        对待裁决的 issue 给答案（待裁决为空时不放此项）
    - 插话        我有话要说，说完再来一轮
    - 再来一轮    直接进下一质询轮
    - 拍板        我定了，出纪要
```

发起人选"裁决"或"插话"后，用纯文本等发起人输入。裁决原文追加进 `裁决记录.md`，格式：

```
## 第 {n} 轮后
- ISSUE-x：{发起人原话}
```

收到后进入第 5 步，裁决与插话作为材料附上。发起人在任何时候说"散会"，进入第 9 步，结论写"未拍板"。

## 第 9 步：纪要

```
# {议题短名}（{YYYY-MM-DD}）

## 结论
{拍板：发起人原话 ／ 散会：未拍板}

## 最终草案
{最后一版草案全文；拍板附裁决时，由「书记」先按裁决出最终版再落盘}

## 决策记录
| ISSUE | 提出席位 | 严重度 | 最终处置 | 理由 |
|---|---|---|---|---|
（整场所有 issue，按编号）

## 未决项
- {最终版 §6 的条目；没有写"无"}

## 轮次
开路轮 {有/无}，质询轮 {n} 轮，过程见同目录 草案-v*.md / issues-*.md / 裁决记录.md
```

未拍板时"结论"一节只写"未拍板"，不得出现主持人建议。
