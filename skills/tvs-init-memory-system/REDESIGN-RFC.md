# tvs-init-memory-system v5 重新设计 RFC

- 状态：**已批准并实施**（2026-06-11 用户全批，P0-P4 已落地为 v5；本文转为设计依据存档）
- 日期：2026-06-11
- 目标（用户原话）：做一个合格的、自己思维方式的记忆工程——**减少 token 使用、留下可读性极强的文档、增加模型准确性和速度**。

## v4.1 已完成（无需批准，纯结构）

- SKILL.md 从 80KB / 1011 行 拆为 ~9KB 主流程 + 8 个按需加载的 references/ 文件。
- 660 行 hook 脚本从"嵌在 Markdown 里让 AI 抄写"改为随包 `scripts/memory-precheck.mjs` **复制安装**：部署 token 成本从约 2 万降到约 2 千，且杜绝抄写错误。
- 内容逻辑零改动，v4 全部特性保留。

## v5 提案（按收益排序，逐条可独立批准）

### P0：记忆模型从"业务档案"改为"决策与红线账本" ⭐⭐ 根治性变更

**问题（用户原话）**：模块档案存了很多不需要的内容、不能保证实时性、消耗大量 token。

**根因**：三个痛点同源——档案记录的大多是**可从代码推导的知识**（模块职责/业务流程/数据契约），这类内容代码一变就过期、AI 用 codegraph 几秒能现场推导、且篇幅大。而**不可推导的知识**（设计决策的为什么、红线、术语映射、踩坑教训）是历史事实，天然不过期、天然短小。

**提案**（三大支柱：导航 / 决策 / 红线——均为不可推导知识，天然耐过期）：
- 取消 `模块档案/` 目录树。全库收敛为 6 个文件：记忆索引（<2KB 常驻）、**业务导航**（第一支柱，见下）、**决策日志**（append-only ADR-lite：日期/模块/决策/为什么/状态，被推翻标"已被 X 取代"而非改写）、**红线与约定**（按模块分节，违反即错的硬约束）、跨分支在研功能地图（保留，codegraph 盲区）、待确认问题。
- **业务导航.md（用户明确的核心诉求）**：每个业务能力一行——`业务能力 | 用户叫法/别名（中英） | 代码入口目录 | 一句话边界`。解决两件事：① 术语锚定（用户说"社区"，AI 知道是 space，不搞错）；② 入口导航（用户说改某业务，AI 直接拿到入口目录，codegraph 从锚点展开，砍掉 grep 试错轮次——这是省 token 的大头）。**修正 v4 H 黑名单**："裸路径罗列不进记忆"维持，但"业务词→入口"的映射必须进——自然语言到代码的锚定在 AST 中不存在，属不可推导知识；路径过期由自检（codegraph_search 校验）+ lint 超龄复审兜底。
- 宪法查询路由改为流水线：用户用业务词提需求 → 查业务导航拿术语与入口 → codegraph 从入口展开结构 → 动手前过该模块红线。
- v4 模块档案必填五项去向：模块职责→删（可推导）；术语→并入业务导航；协作契约+红线→并入红线文件；设计决策→并入决策日志。
- 维护子 Agent 的动作从"重写档案"降为"追加决策 + 改红线 + 偶尔标记取代"。
- 总量软上限从 100KB 降到 32KB。
- 借鉴 omc wiki 的 lint：`--lint-memory` 扩展孤儿文件（索引外）、`[[链]]`断裂、>180 天未触碰条目标记"提请复审"。**不借鉴**其会话尾自动抓取（噪音放大器）。
- 迁移：一次性蒸馏存量档案（抽决策/红线/术语，其余删），可由维护子 Agent 执行并人工 review。

**与原生记忆分流**（并入 P4 宪法定位）：个人偏好→Claude 原生记忆；团队决策红线→.memory；临时笔记→不存。

### P1：给记忆加"被读取"的衡量回路 ⭐ 最重要

**问题**：现在整套系统优化的都是"怎么写好记忆"，但没有任何证据表明 `.memory` 被主 Agent 读了、读了有没有用。写而不读的记忆是纯 token 负债。

**提案**：宪法第 2 条要求"决策前先读记忆索引"，配套在 `--status` 里增加一个朴素信号：统计 `记忆索引.md` 的 atime/被引用情况做不到（atime 不可靠），改为**人工回路**——每月跑一次 `--lint-memory` 时顺便自问三个问题（写进 lint 输出）：①最近 AI 放错过代码位置吗？②最近 AI 重复造过轮子吗？③你自己上次查 .memory 是什么时候？三问皆否 → 该精简而不是扩充。

**代价**：几行脚本输出。**不做的风险**：系统永远在凭感觉迭代。

### P2：维护员正文瘦身（约 -40%）

**问题**：`references/maintainer-agent.md` 的子 Agent 正文约 130 行，每次维护触发都全量进上下文。其中"v4 调整说明"、"这条针对 2026-05-25 事故"等**给维护者（你）看的历史注解**对执行 Agent 是噪音。

**提案**：正文只留可执行规则；历史依据移到 design-notes.md。预计 130 行 → 80 行以内。

### P3：跨成员去重 / 时间衰减——保留但默认简化

**问题**：v4 的分支感知 + 时间衰减 + 跨成员去重是为多人团队设计的。运行期零 AI 成本（纯代码），所以**不删**；但单人项目里跨成员去重永远不命中，机读锚点却要随每次 mark-done 改动入库文件，产生无意义 git diff。

**提案**：CONFIG 加一个 `teamMode: true|false` 开关，部署访谈时问一句"这个项目是单人还是多人"；单人模式下锚点只写 state 文件不写入库文件。

### P4：宿主能力探测 + 个人记忆层差异化供给（不绑定 Claude）

**问题**：① Claude Code 自带项目记忆，与 `.memory` 概念重叠，使用者困惑该信什么；② 若把"个人偏好"职责让位给 Claude 原生记忆，系统在 Cursor / Codex 等无原生记忆的宿主上就缺了一块——**系统完整性不得依赖任何宿主私有能力**（用户明确要求，与 codegraph 降级同一哲学）。

**提案**（初始化时按宿主能力差异化供给，三层记忆每层有兜底）：
- **团队层**：`.memory/` 入库 6 文件（P0 模型），所有宿主一致，本系统自己提供。
- **个人层**：初始化时探测宿主——
  - 宿主有原生个人记忆（Claude Code）→ 不重复建设，宪法写明"个人偏好、用户纠正过的做法归原生记忆；冲突时以入库 `.memory` 为准"。
  - 宿主无原生记忆（Cursor / Codex / 其他）→ 额外创建 `.memory/个人偏好.md`（**gitignored**，单机层），宪法指示 AI 主动读写它，承担与 Claude 原生记忆等价的职责（个人习惯/纠错记录/沟通偏好），绝不写入入库文件。
- **结构层**：codegraph，缺失降级 git plumbing / grep（v4 已有）。
- 落点：宿主识别（第 0 节）增加"原生个人记忆"探测项；宪法模板按探测结果生成对应分流条款；gitignore 规则随之增加个人偏好文件。

### 暂不动的

- 4 个 preset、H/G 防膨胀、lint-memory、基线机制：v4 核心，运行良好。
- 不引入向量检索/RAG：`.memory` 总量软上限 100KB，全文塞索引都够，检索是过度设计。

## 批准方式

回复"批准 P1 P2"或"全批"或逐条调整即可，对应改动会落到 scripts/ 与 references/，SKILL.md 主流程基本不动。
