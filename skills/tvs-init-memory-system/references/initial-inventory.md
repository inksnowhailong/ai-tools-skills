# 首次记忆盘点（收尾询问，用户同意才执行）

> 账本骨架刚建好时六个文件全是空的，业务导航（核心价值：术语锚定 + 入口导航）的冷启动靠这次盘点完成。
> 这是「不直接写记忆内容」规则的**唯一初始化例外**——因为"用户怎么叫它"只有用户本人知道，后台子 Agent 永远拿不到。

## 范围（只填这两样，其余不动）

- ✅ 业务导航.md：术语 ↔ 入口初版
- ✅ 红线与约定.md：仅当用户主动给出红线
- ❌ 决策日志.md：保持空白，append-only 从今天开始。**不要从 git log 倒灌历史决策**——commit message 还原不出"为什么"，倒灌只会制造噪音。
- ❌ 模块职责 / 流程 / 契约等可推导内容：照常禁止。

## 流程（主 Agent 交互式，控制在 10 分钟内）

1. **列模块**：用 codegraph_files（无则目录树）列出项目顶层业务模块，过滤纯工具目录（utils / config / scripts / assets 之类）。一次性列给用户看，让用户先删掉不关心的。
2. **逐个问叫法**：每个模块问一句"这块你平时叫它什么？有没有别名（中英都算）？"用户说"跳过"就不填，不追问。
3. **AI 草拟边界**：用户确认叫法后，由你草拟"一句话边界"，用户确认或修正——不要让用户自己写。
4. **填表**：写入 `.memory/业务导航.md`，删除示例占位行。
5. **问红线**：最后问一句"改代码有没有绝对不能踩的红线？没有就留空"。有则按模块写入 `.memory/红线与约定.md`。

## 完成标志

业务导航里至少有用户确认过的真实行（数量 = 用户没跳过的模块数），无占位行残留。输出表格预览 + 一句确认，结束盘点，回到收尾停止。
