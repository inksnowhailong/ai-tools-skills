# 产物 4：.memory/ 骨架（v5 账本模型）

> v5 核心：只存**不可推导的知识**——导航（你怎么叫它、它在哪）、决策（为什么是这样）、红线（什么不能碰）。可推导内容（模块职责/业务流程/数据契约）一律不存：它们必然随代码过期，且 codegraph 几秒能现场推导。**不建模块档案目录树。**

## 文件清单

```text
.memory/
├── 记忆索引.md            常驻入口（<2KB），路由流水线 + 文件清单 + 反模式
├── 业务导航.md            第一支柱：术语 ↔ 模块 ↔ 代码入口
├── 决策日志.md            第二支柱：append-only ADR-lite
├── 红线与约定.md          第三支柱：按模块分节的硬约束
├── 跨分支在研功能地图.md   codegraph 盲区 + 团队维护元数据（机读锚点）
├── 待确认问题.md          子 Agent 不确定的内容写这里，由人审定
└── 个人偏好.md            【条件创建】仅当宿主无原生个人记忆时建（gitignored）
```

## 各文件骨架

### 记忆索引.md

````markdown
# 记忆索引

> `.memory/` 入口。写代码 / 做架构决策前先读本文件。由 project-memory-maintainer 维护。

## 查询流水线（按这个顺序走）

```text
用户用业务词提需求 → 查 业务导航.md 拿正确术语和代码入口
                  → codegraph 从入口展开结构（无 codegraph 则 grep/read）
                  → 动手前过一遍 红线与约定.md 该模块一节
```

## 文件清单

| 文件 | 回答什么 |
|---|---|
| 业务导航.md | 这个业务叫什么、代码入口在哪 |
| 决策日志.md | 为什么是现在这个设计、踩过什么坑 |
| 红线与约定.md | 什么不能碰、违反即错的约束 |
| 跨分支在研功能地图.md | 哪个功能在哪个分支迭代 |
| 待确认问题.md | 尚未确认的疑点 |

## 反模式

- ❌ 把记忆当代码地图翻"X 函数在哪个文件"——纯结构查 codegraph。
- ❌ 记录模块职责 / 业务流程 / 数据契约——可推导内容必然过期，不进记忆。
- ❌ 同一信息两处都写——纯结构归 codegraph，业务语义归 `.memory`。
````

### 决策日志.md

````markdown
# 决策日志

> append-only：只追加，不改写。决策被推翻时不删旧条目，在旧条目标"已被 YYYY-MM-DD 条目取代"。
> 何时记：方向性技术/业务选择、被否决的备选方案及原因、事故教训。

## 2026-01-01 · 示例模块 · 示例决策标题（占位，首条真实决策时删除）
为什么：一句话讲清当时的约束和理由。
状态：✅ 生效
````
