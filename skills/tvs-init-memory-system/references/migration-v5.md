# 存量迁移：v4 模块档案 → v5 账本（蒸馏，不是删库）

> 适用：项目已有 v4 的 `.memory/`（含 `模块档案/` 目录树、`项目总览.md`、`术语表.md`）。
> 原则：**抽出不可推导的知识填进账本，其余删除**。迁移产物必须供用户 review（git diff）后再入库，不要静默替换。

## 步骤

### 1. 确认基线安全

`.memory/` 应已入库（v3 起默认）——git 历史就是备份。未入库的话先让用户提交一次现状。

### 2. 建立 v5 骨架

按 `memory-skeleton.md` 创建六文件（已存在的跨分支地图、待确认问题保留原内容）。

### 3. 逐模块蒸馏 `模块档案/<模块>/总览.md`

对每份档案，把内容按去向分拣：

| 旧档案内容 | 去向 |
|---|---|
| 术语 / 别名 / 同义词 + barrel 入口路径 | → `业务导航.md` 一行（能力 / 叫法 / 入口 / 一句话边界） |
| 设计决策（"为什么是这样"） | → `决策日志.md` 追加条目；日期不可考时用 `git log --follow --format=%ad -1` 取该档案最后修改日期，并标"（迁移自 v4 档案）" |
| 红线 / 已知风险 / 跨模块协作契约（谁不能调谁） | → `红线与约定.md` 该模块一节 |
| 模块职责描述、业务流程叙述、数据契约、函数签名、调用关系 | → **删除**（可推导内容，codegraph 现场可答） |
| 拿不准真假的陈述 | → `待确认问题.md`，不要当事实迁移 |

### 4. 蒸馏全局文件

- `项目总览.md`：工程风格/约定类条目 → `红线与约定.md` 的"全局"节；项目介绍性叙述删除。迁移完删除此文件。
- `术语表.md`：并入 `业务导航.md` 的叫法/别名列。迁移完删除此文件。
- `记忆索引.md`：按 v5 骨架重写（查询流水线 + 文件清单 + 反模式）。

### 5. 删除 `模块档案/` 目录树

所有档案蒸馏完毕后整树删除。删除前确认每份档案都过了第 3 步分拣。

### 6. 校验与收尾

```bash
node <宿主hooks路径>/memory-precheck.mjs --lint-memory   # 孤儿/断链/噪音应为 0
```

- 业务导航里的每个入口路径用 `codegraph_search`（或 `git cat-file -e <集成线>:<path>`）校验存在。
- 向用户展示迁移摘要（蒸馏出 N 条决策 / M 条红线 / K 行导航，删除约 X KB 可推导内容），由用户 review git diff 后提交。
- 用户确认后 `--mark-done` 刷新基线。

## 执行者

可由 `project-memory-maintainer` 子 Agent 执行（一次性大任务，建议提醒用户这次会比日常维护久），也可由主 Agent 在用户明确要求迁移时执行——迁移属于"用户显式发起的一次性工程动作"，不受宪法第 1 条日常写入边界限制，但完成后要声明。
