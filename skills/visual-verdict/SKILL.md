# 视觉验收

用于对比当前 UI 截图与一张或多张参考图，并给出可指导下一轮修改的视觉 QA 结论。

## 使用场景

当出现以下情况时使用：

- 任务包含视觉还原或设计一致性要求。
- 用户提供了生成截图和参考图。
- 继续改 UI 前需要明确通过、返工或失败。
- 用户问页面“像不像参考图”“还原度怎么样”。

## 输入

- `reference_images[]`：一张或多张参考图路径。
- `generated_screenshot`：当前生成页面截图路径。
- `category_hint`：可选，说明页面类型，例如 dashboard、feed、landing-page、settings、mobile。

## 输出约定

只有当用户明确要求机器可读结果时，才输出 JSON：

```json
{
  "score": 0,
  "verdict": "revise",
  "category_match": false,
  "differences": ["..."],
  "suggestions": ["..."],
  "reasoning": "简短说明"
}
```

字段规则：

- `score`：0 到 100 的整数。
- `verdict`：`pass`、`revise` 或 `fail`。
- `category_match`：生成截图是否符合目标页面类型和视觉风格。
- `differences[]`：列出具体视觉差异，包括布局、间距、字体、颜色、层级、密度、交互暗示。
- `suggestions[]`：给出与差异对应的下一步修改建议。
- `reasoning`：1-2 句话总结判断依据。

如果用户只需要普通解释，用简洁中文说明同样的信息。

## 通过阈值

- 默认通过阈值为 90 分以上。
- 如果 `score < 90`，必须指出具体差异，并建议下一轮修改重点。
- 不要在最新截图达到阈值前宣布视觉任务完成，除非用户明确接受剩余差异。

## 诊断方式

当视觉差异难以判断时：

1. 以人工视觉判断作为主结论。
2. 像素差异、叠图或测量工具只能作为辅助证据。
3. 把视觉热点转成具体差异和可执行建议。

## 审查重点

重点检查：

- 整体布局与比例。
- 间距节奏。
- 字体大小、字重和层级。
- 色彩、对比度和品牌一致性。
- 组件样式。
- 对齐、密度和留白。
- 多视口截图中的响应式表现。
- 是否存在明显的通用 AI UI 味道。
