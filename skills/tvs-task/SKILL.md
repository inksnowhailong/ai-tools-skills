# 任务记录与追踪

将自然语言对话转换为结构化任务，存入单一文件 `~/.tasklog/active.md`。核心原则：**极低摩擦**——说话即记录，一句话即完成，不需要打开任何界面。

## 存储

唯一文件：`~/.tasklog/active.md`

- **完成即删**：任务完成确认后直接从 active.md 删除整个任务块，不留 ✅ 存档——文件里只放活着的任务
- 任务 ID 全局自增（T-001、T-002…），**从文件头 `_下个ID：T-xxx_` 计数行读取**（完成任务会被删除，不能再用"最大 ID + 1"推算）；每次创建任务后把计数行 +1

## active.md 格式

```markdown
# 任务清单

_最后更新：{日期}_
_下个ID：T-{nnn}_

---

## T-001 · {任务标题}

- **状态**：{🔄 进行中 / 📋 待开始 / ✅ 完成 / 🕐 停滞}
- **优先级**：{高 / 中 / 低}
- **创建**：{YYYY-MM-DD}
- **更新**：{YYYY-MM-DD}
- **项目**：
  - `{仓库绝对路径}` — `{分支名}`

### 进度节点
- [x] {已完成子项}
- [ ] {待完成子项}

### 迭代记录
#### v1 · {YYYY-MM-DD} · {简述}
状态：✅ 完成 / 🔄 进行中
说明：{可选}

---
```

**停滞判断**：状态为"进行中"且距 **更新** 日期超过 5 天，显示 🕐 停滞。

## 触发识别

**优先判断意图，关键词只是辅助信号。** AI 应先判断用户是否在描述一件要做或已做的工作事项，再决定触发哪个操作——不要死扣关键词，也不要把日常口语（"我要做饭"）当任务。

| 信号 | 操作 |
|------|------|
| 明确指令："记录任务" / "新建任务" / "明确任务" | → 创建任务 |
| 口语描述工作事项："帮我记一下xxx" / "下午要改xxx" / "领导说要xxx" / "需要做xxx" | → 创建任务 |
| 列举多个待做事项（含编号、顿号、"第一/第二"、"三件事"等结构） | → 批量拆分 |
| "建个分支 feature/xxx" / "新建分支 xxx" / "checkout -b xxx" | → 被动建议创建任务 |
| **"xxx 完了" 且后面没有"但/还要/继续/不过"转折** | → 完成任务 |
| **"xxx 完了，但/还要/继续 yyy"（完成 + 转折）** | → 迭代追加（不标完成） |
| "T-xxx 继续" / "还要迭代" / "T-xxx 没完，还要..." | → 迭代追加 |
| **git push 成功 / PR 合并 / git merge 完成**（对话中出现 push 输出、PR 合并通知、或用户说"推上去了/合了"） | → **自动触发进度更新** |
| "任务情况" / "看看任务" / "有啥在做" / "任务表" / "进度怎样" | → 渲染状态表 |
| "上周做了啥" / "这周完成了" / "帮我整理完成的任务" | → 周回顾摘要 |

**完成 vs 迭代追加的判断规则（最容易混淆）：**
- `"xxx 搞完了"` → 完成
- `"xxx 搞完了，还要加 yyy"` → **迭代追加**，同时把上一迭代标完成、追加新迭代块
- `"xxx 没完全完，还差 yyy"` → **仅追加进度节点**，状态不变

## 操作流程

**写操作后回显状态表**：凡是改动了 active.md 的操作（创建任务、完成任务、迭代追加、push/merge 触发更新），主流程都在回复末尾回显**增量视图**——运行 `node "{SKILL_DIR}/scripts/render.mjs" --ids {受影响的T-xxx}`（多个用逗号连），把输出原样贴上。脚本会只渲染受影响项目组、命中行标 `← 本次`、表前带全局总览。用户显式查看（"看任务/任务表"）才渲染全量表。注意：回显前需确保写盘已完成（脚本读的是磁盘文件）——若子代理仍在异步写盘，则按"已知变更后状态"手动渲染同格式增量表，不等写盘。

### 创建任务

1. **去重检查**（主流程执行，不走子代理）：读 `~/.tasklog/active.md`，按结构化 key 判断是否重复。

   **去重 key 提取**：① 仓库路径（明确提到的或当前工作目录）② 功能域关键词（3-5 个核心词：技术术语/产品名/模块名，如 "Stripe"、"checkout"、"搜索"）。

   **命中逻辑**：
   - 仓库路径**完全相同** → 功能域关键词有**任何重叠** → 必须列出候选确认，不自动创建
   - 仓库路径不同 → 功能域重叠度极高（80%+）才列出候选
   - 无仓库信息（对话中未提） → 功能描述重叠度高才询问

   命中 → 列出候选，询问"是不是 T-xxx？"，用户确认后走迭代追加。

2. **解析任务**（主流程）：
   - 从自然语言提取：标题、优先级（从上下文推断，无法判断默认"中"）、涉及项目（若在对话或当前目录能识别）、分支（若提到）、子任务列表
   - 多任务输入（"三件事：xxx / yyy / zzz"）→ 逐条生成多个任务块

3. **派子代理写文件**：
   - 读当前 `~/.tasklog/active.md`（不存在则创建）
   - 计算下一个 ID
   - 在文件末尾追加任务块
   - 更新 `_最后更新_` 日期

4. **主流程返回**：告知用户已建立 T-xxx，不等子代理完成后再响应。

### 被动建议（分支创建）

检测到用户提及新建 git 分支时，**不强制创建**，主动询问：

```
检测到你提到新建分支 feature/xxx，要为它建个任务吗？（不建直接忽略）
```

用户确认才走创建流程。

### 完成任务

1. **先判断是否含转折**：输入中有"但/还要/继续/不过/就是还差"等转折词 → 走**迭代追加**，不走完成。

2. **匹配规则（按优先级）**：
   - 输入含 `T-xxx` 格式 ID → 直接命中，无需确认
   - 输入含任务标题关键词 → 在**进行中/待开始**任务里模糊匹配
     - 唯一匹配 → 直接标完成
     - 多个候选 → 列出让用户选，不要猜
     - 完全匹配不到 → 告知用户没找到相关进行中任务，询问是否要新建

3. **默认 git 核查**（有分支信息时自动执行，无需用户额外说）：
   - 子代理对任务 `项目` 数组里每个仓库执行：
     ```bash
     cd {仓库路径} && git branch --merged main 2>/dev/null | grep {分支名} || git branch --merged master 2>/dev/null | grep {分支名}
     ```
   - 跨分支链（feature→dev→main/master）：直查不到时，检查间接合并链：
     ```bash
     git log main --merges --oneline | grep -i "dev"
     git branch --merged main | grep dev
     ```
   - 查到合并 → **从 active.md 删除该任务块**（完成即删，不留存档）
   - **未查到合并** → 提示"分支尚未合入主线，确认完成并删除？"，用户确认后再删
   - 无分支信息 → 跳过 git 核查，直接删除任务块

### 追加迭代（不新建任务）

1. 定位到已有任务（ID 或模糊匹配，规则同完成任务）
2. 派子代理（以下为原子操作，一次完成）：
   - 若有迭代记录且最新一条状态为"进行中" → **先把该条改为 ✅ 完成**
   - 在 `迭代记录` 末尾追加新版本块：
     ```markdown
     #### v{n} · {今日} · {本次迭代简述}
     状态：🔄 进行中
     说明：{用户说的新需求}
     ```
   - 任务整体状态改回 `🔄 进行中`
   - 更新 `更新` 日期
3. 主流程告知用户：T-xxx 已追加 v{n} 迭代，继续进行中。

### Push / Merge 触发进度更新

检测到以下信号时自动执行（无需用户说"完成"）：
- 对话中出现 `git push` 成功输出（含分支名 / remote 地址）
- 用户说"推上去了" / "合了" / "PR 合了" / "merge 了"
- 工具输出显示 PR 合并或 branch 已删除

**流程**：
1. **定位任务**：从信号中提取仓库路径 + 分支名，在 进行中/待开始 任务里精确匹配 `项目` 字段。找不到 → 跳过，不打扰。
2. **进度节点自动勾选**：对该仓库执行：
   ```bash
   cd {仓库路径} && git log {分支名} --oneline -20
   ```
   将 commit message 关键词与进度节点文本做模糊匹配，自动勾选命中的节点（相似度 ≥ 60%），未命中的保持原样。
3. **合并到主线检测**：同"完成任务"的 git 核查逻辑，检查 feature→dev→main 链。
   - **已合入主线** → 询问用户"T-xxx 分支已合入主线，要完成并删除吗？"
   - **仅 push，未合主线** → 更新进度节点 checkbox，任务状态保持进行中，备注"最新 push: {日期}"

4. 确认或用户回复"是" → 走完成任务流程（派子代理删除任务块）。

### 渲染状态表

**优先跑本 skill 自带脚本**（零依赖，node 内置模块，输出即最终 markdown，原样贴进回复）：

```bash
node "{SKILL_DIR}/scripts/render.mjs"                # 全量
node "{SKILL_DIR}/scripts/render.mjs" --ids T-008    # 增量：只渲染含这些任务的项目组，命中行标 ← 本次
```

`{SKILL_DIR}` 即本 SKILL.md 所在目录（skill 启动时已给出 Base directory）。node 不可用或脚本报错时，按下方格式规范手动渲染兜底。

**格式规范**（脚本输出 = 此格式，手动兜底也按此）：**项目是顶级分类，但全表只用一张宽表**：项目列只在每组首行填写（视觉合并单元格效果），组内后续行该列留空；不为每个项目单独起表、组间不插空行，纵向零浪费。**跨多个项目的任务在每个相关项目组下各出现一行**（ID 后标 ⇄，分支列填该项目对应的分支）；无项目信息的任务归入「未关联」组。表前给一行全局总览。

```
任务 12 ｜ 🔄3 📋5 ✅4

| 项目 | ID | 任务 | 状态 | 优先级 | 进度 | 分支 |
|------|----|------|------|--------|------|------|
| **crestrail** | T-002 | Stripe 对接改工作流引擎 | 🔄 进行中 | 中 | 1/6 | feature/community-plugin-pay |
| | T-012 | 工作流画布右键菜单 | 📋 待开始 | 低 | 0/3 | feature/community-plugin-pay |
| **studio_web** | T-001 ⇄ | 支付中心交互样式优化 | 🔄 进行中 | 中 | 0/3 | feat/plugin-add-payment-center-20260605 |
| **shirehub-central** | T-001 ⇄ | 支付中心交互样式优化 | 🔄 进行中 | 中 | 0/3 | feat/community-add-plugin-payment-20260602 |
| **shirehub** | T-005 | 发帖 YouTube 链接解析 | 📋 待开始 | 中 | 6/8 | feat/create-post-iteration-20260527 |
```

规则：
- **项目组排序**：含进行中任务的项目在前，其余按组内最近更新降序；「未关联」永远最后
- **组内行排序**：进行中 → 停滞 → 待开始
- 分支列展示该任务在**当前项目**下对应的分支（同一任务在不同项目组下分支可不同）
- 进度列从"进度节点"中计算已勾选 / 总数

### 周回顾摘要

完成任务即删，active.md 不保留完成历史——周回顾从 git 取材：对 active.md 里出现过的各仓库执行 `git log --since="1 week ago" --oneline`（必要时加 `--author`），按仓库汇总一份完成清单。不生成周报正文，只给清单，写周报是用户自己的事。

## 子代理规范

以下操作统一走子代理（后台非阻塞）：

- 写/修改 `~/.tasklog/active.md`
- git 分支合并检查

以下操作主流程直接执行（快，不需要后台）：

- 读 `~/.tasklog/active.md`（去重检查、渲染表格、周回顾）
- 解析自然语言、模糊匹配任务

子代理调用示例（Claude Code 环境）：

```
派子代理执行以下操作：
1. 读取 ~/.tasklog/active.md
2. {具体修改说明}
3. 写回文件
完成后无需回复。
```

其他 AI 环境（Cursor 等）：使用等效的后台任务或异步工具；若无法后台执行，则同步执行但告知用户"正在写入…"。

## 优先级推断规则

| 上下文信号 | 推断优先级 |
|-----------|----------|
| "领导说" / "老板要" / "今天必须" / "紧急" | 高 |
| "有空" / "顺便" / "不急" / "想做" | 低 |
| 无明确信号 | 中 |

## 注意事项

- **不提醒、不催促**：本 Skill 只做记录和查询，不主动推送任务提醒。
- **不写周报**：周回顾只给清单，周报正文由用户自己完成。
- **完成需有信号**：口头"完了"或检测到 push/merge 才触发完成流程；有分支信息时默认跑 git 核查，未合入主线会提示确认而非静默删除。
- **文件路径**：`~/.tasklog/` 在 Windows 上为 `%USERPROFILE%\.tasklog\`，在 macOS/Linux 上为 `~/.tasklog/`；子代理写文件时按当前平台处理路径。
