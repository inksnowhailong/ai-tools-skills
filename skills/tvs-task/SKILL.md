# 任务记录与追踪

将自然语言对话转换为结构化任务，存入 `~/.tasklog/`（活任务 `active.md`、归档 `archive.md`、候选忽略名单 `ignore.txt`）。核心原则：**极低摩擦**——说话即记录，一句话即完成，不需要打开任何界面。

## 设计理念：git 状态驱动 + 对话增强

旧版只靠"对话里 AI 注意到信号"做检测（单一传感器 = 用户的嘴），会漏：① 在终端静默 merge 后任务一直挂着；② 直接 `checkout -b` 开干、没在对话里说，新任务建不出来。现改为 **git 状态驱动 + 对话增强**：用确定性脚本 `scripts/scan.mjs` 扫真实 git 状态来检测"已合并应归档"、"应重新打开（reopen）"和"未跟踪的新分支候选"，对话层降级为补充信号。

**主干动态识别**：每个 repo 的「主分支」与「集成/测试分支」都由脚本**动态识别**，不再硬编码 main/master：
- **主分支**：① 优先 `git symbolic-ref --short refs/remotes/origin/HEAD` 去掉 `origin/` 前缀（远端默认分支，最权威）→ ② 取不到则本地依次验证 `main`、`master` 取第一个存在的 → ③ 都没有则该 repo 整体跳过。做合并比较时，主分支名会解析成一个真实存在的 ref：优先本地 head（`refs/heads/<名>`），不存在则用远端跟踪 `origin/<名>`（兜 company repo 本地主分支缺失/滞后）。
- **集成/测试分支**：在别名集合 `{develop, dev, test, testing, staging, uat}` 里返回该 repo 真实存在的本地分支。**仅用于排除**：与主分支一起组成「主干集合」，主干分支永不进新任务候选。

**完成语义 = 只认主分支**：任务完成的唯一标准是它的每个 (repo, branch) 对都已合入该 repo 的**主分支**（`git merge-base --is-ancestor <分支> <主分支ref>`，祖先检测天然覆盖 feature→dev→main 的间接合并链）。**合入测试/集成分支（develop/test 等）不算完成**，任务仍进行中——只有合进主分支才归档。

## 存储

- `~/.tasklog/active.md`：活着的任务（文件里只放进行中/待开始/停滞）
- `~/.tasklog/archive.md`：已归档（已完成）任务，格式同 active.md 任务块、字段区多一行 `- **完成**：YYYY-MM-DD`，最近完成置顶
- `~/.tasklog/ignore.txt`：新分支候选忽略名单（详见「git 状态扫描」一节）

- **完成即归档**：任务完成确认后把整个任务块从 active.md **移入 archive.md**（加完成日期），而非丢弃；archive.md 留档 **30 天**，超 30 天的归档块在下次 `--apply` 写入时自动清理
- 任务 ID 全局自增（T-001、T-002…），**从文件头 `_下个ID：T-xxx_` 计数行读取**（完成任务会被移走，不能再用"最大 ID + 1"推算）；每次创建任务后把计数行 +1（归档不回退计数）

## active.md 格式

```markdown
# 任务清单

_最后更新：{日期}_
_下个ID：T-{nnn}_

---

## T-001 · {任务标题}

- **状态**：{🔄 进行中 / 📋 待开始 / ✅ 完成 / 🕐 停滞}
- **优先级**：{高 / 中 / 低}
- **创建**：{YYYY-MM-DD}
- **更新**：{YYYY-MM-DD}
- **项目**：
  - `{仓库绝对路径}` — `{分支名}`

### 进度节点
- [x] {已完成子项}
- [ ] {待完成子项}

### 迭代记录
#### v1 · {YYYY-MM-DD} · {简述}
状态：✅ 完成 / 🔄 进行中
说明：{可选}

---
```

**停滞判断**：状态为"进行中"且距 **更新** 日期超过 5 天，显示 🕐 停滞。该「更新」日期由 `scan.mjs --apply` 在每次落地时**按 git 驱动**刷新为该任务各分支最后一次提交日期的最新者——所以停滞反映的是真实代码活跃度，而非对话有没有提到它。

## 触发识别

**优先判断意图，关键词只是辅助信号。** AI 应先判断用户是否在描述一件要做或已做的工作事项，再决定触发哪个操作——不要死扣关键词，也不要把日常口语（"我要做饭"）当任务。

| 信号 | 操作 |
|------|------|
| 明确指令："记录任务" / "新建任务" / "明确任务" | → 创建任务 |
| 口语描述工作事项："帮我记一下xxx" / "下午要改xxx" / "领导说要xxx" / "需要做xxx" | → 创建任务 |
| 列举多个待做事项（含编号、顿号、"第一/第二"、"三件事"等结构） | → 批量拆分 |
| "建个分支 feature/xxx" / "新建分支 xxx" / "checkout -b xxx" | → 被动建议创建任务 |
| **"xxx 完了" 且后面没有"但/还要/继续/不过"转折** | → 完成任务 |
| **"xxx 完了，但/还要/继续 yyy"（完成 + 转折）** | → 迭代追加（不标完成） |
| "T-xxx 继续" / "还要迭代" / "T-xxx 没完，还要..." | → 迭代追加 |
| **git push 成功 / PR 合并 / git merge 完成**（对话中出现 push 输出、PR 合并通知、或用户说"推上去了/合了"） | → **自动触发进度更新** |
| "任务情况" / "看看任务" / "有啥在做" / "任务表" / "进度怎样" / **会话开始时** | → **先跑 git 扫描** 再渲染状态表 |
| "上周做了啥" / "这周完成了" / "帮我整理完成的任务" | → 周回顾摘要 |

**完成 vs 迭代追加的判断规则（最容易混淆）：**
- `"xxx 搞完了"` → 完成
- `"xxx 搞完了，还要加 yyy"` → **迭代追加**，同时把上一迭代标完成、追加新迭代块
- `"xxx 没完全完，还差 yyy"` → **仅追加进度节点**，状态不变

## 操作流程

**写操作后回显状态表**：凡是改动了 active.md 的操作（创建任务、完成任务、迭代追加、push/merge 触发更新），主流程都在回复末尾回显**增量视图**——运行 `node "{SKILL_DIR}/scripts/render.mjs" --ids {受影响的T-xxx}`（多个用逗号连），把输出原样贴上。脚本会只渲染受影响项目组、命中行标 `← 本次`、表前带全局总览。用户显式查看（"看任务/任务表"）才渲染全量表。注意：回显前需确保写盘已完成（脚本读的是磁盘文件）——若子代理仍在异步写盘，则按"已知变更后状态"手动渲染同格式增量表，不等写盘。

### 创建任务

1. **去重检查**（主流程执行，不走子代理）：读 `~/.tasklog/active.md`，按结构化 key 判断是否重复。

   **去重 key 提取**：① 仓库路径（明确提到的或当前工作目录）② 功能域关键词（3-5 个核心词：技术术语/产品名/模块名，如 "Stripe"、"checkout"、"搜索"）。

   **命中逻辑**：
   - 仓库路径**完全相同** → 功能域关键词有**任何重叠** → 必须列出候选确认，不自动创建
   - 仓库路径不同 → 功能域重叠度极高（80%+）才列出候选
   - 无仓库信息（对话中未提） → 功能描述重叠度高才询问

   命中 → 列出候选，询问"是不是 T-xxx？"，用户确认后走迭代追加。

2. **解析任务**（主流程）：
   - 从自然语言提取：标题、优先级（从上下文推断，无法判断默认"中"）、涉及项目（若在对话或当前目录能识别）、分支（若提到）、子任务列表
   - 多任务输入（"三件事：xxx / yyy / zzz"）→ 逐条生成多个任务块

3. **派子代理写文件**：
   - 读当前 `~/.tasklog/active.md`（不存在则创建）
   - 计算下一个 ID
   - 在文件末尾追加任务块
   - 更新 `_最后更新_` 日期

4. **主流程返回**：告知用户已建立 T-xxx，不等子代理完成后再响应。

### 被动建议（分支创建）

检测到用户提及新建 git 分支时，**不强制创建**，主动询问：

```
检测到你提到新建分支 feature/xxx，要为它建个任务吗？（不建直接忽略）
```

用户确认才走创建流程。

### 完成任务

1. **先判断是否含转折**：输入中有"但/还要/继续/不过/就是还差"等转折词 → 走**迭代追加**，不走完成。

2. **匹配规则（按优先级）**：
   - 输入含 `T-xxx` 格式 ID → 直接命中，无需确认
   - 输入含任务标题关键词 → 在**进行中/待开始**任务里模糊匹配
     - 唯一匹配 → 直接标完成
     - 多个候选 → 列出让用户选，不要猜
     - 完全匹配不到 → 告知用户没找到相关进行中任务，询问是否要新建

3. **默认 git 核查**（有分支信息时自动执行，无需用户额外说）：
   - 子代理对任务 `项目` 数组里每个仓库执行：先动态识别该 repo 的**主分支**（origin/HEAD → 本地 main/master），解析成真实 ref（本地 head 优先，否则 `origin/<名>`），再做祖先检测（天然覆盖 feature→dev→main 的间接合并链：分支提交只要经任何路径进了主分支，分支尖就是主分支的祖先）：
     ```bash
     cd {仓库路径} && git merge-base --is-ancestor {分支名} {该repo主分支ref} && echo merged
     ```
   - **只认主分支**：合入 develop/test 等集成/测试分支**不算完成**，任务仍进行中。
   - 注意：squash merge 会重写提交，祖先检测查不到——这正是下面"未查到合并 → 提示确认"兜底存在的原因，查不到不代表没合，交给用户确认。
   - 查到合并 → **把该任务块从 active.md 移入 archive.md 并加 `- **完成**：今日` 行**（完成即归档，留档 30 天）
   - **未查到合并** → 提示"分支尚未合入主分支，确认完成并归档？"，用户确认后再移入 archive.md
   - 无分支信息 → 跳过 git 核查，直接把任务块移入 archive.md

### 追加迭代（不新建任务）

1. 定位到已有任务（ID 或模糊匹配，规则同完成任务）
2. 派子代理（以下为原子操作，一次完成）：
   - 若有迭代记录且最新一条状态为"进行中" → **先把该条改为 ✅ 完成**
   - 在 `迭代记录` 末尾追加新版本块：
     ```markdown
     #### v{n} · {今日} · {本次迭代简述}
     状态：🔄 进行中
     说明：{用户说的新需求}
     ```
   - 任务整体状态改回 `🔄 进行中`
   - 更新 `更新` 日期
3. 主流程告知用户：T-xxx 已追加 v{n} 迭代，继续进行中。

### Push / Merge 触发进度更新

检测到以下信号时自动执行（无需用户说"完成"）：
- 对话中出现 `git push` 成功输出（含分支名 / remote 地址）
- 用户说"推上去了" / "合了" / "PR 合了" / "merge 了"
- 工具输出显示 PR 合并或 branch 已删除

**流程**：
1. **定位任务**：从信号中提取仓库路径 + 分支名，在 进行中/待开始 任务里精确匹配 `项目` 字段。找不到 → 跳过，不打扰。
2. **进度节点自动勾选**：对该仓库执行：
   ```bash
   cd {仓库路径} && git log {分支名} --oneline -20
   ```
   将 commit message 关键词与进度节点文本做模糊匹配，自动勾选命中的节点（相似度 ≥ 60%），未命中的保持原样。
3. **合并到主分支检测**：同"完成任务"的 git 核查逻辑（动态识别该 repo 主分支，只认主分支，合入测试/集成分支不算）。
   - **已合入主分支** → 询问用户"T-xxx 分支已合入主分支，要完成并归档吗？"
   - **仅 push 或仅合入测试/集成分支，未合主分支** → 更新进度节点 checkbox，任务状态保持进行中，备注"最新 push: {日期}"

4. 确认或用户回复"是" → 走完成任务流程（派子代理把任务块移入 archive.md 并加完成日期）。

### 渲染状态表

**优先跑本 skill 自带脚本**（零依赖，node 内置模块，输出即最终 markdown，原样贴进回复）：

```bash
node "{SKILL_DIR}/scripts/render.mjs"                # 全量
node "{SKILL_DIR}/scripts/render.mjs" --ids T-008    # 增量：只渲染含这些任务的项目组，命中行标 ← 本次
```

`{SKILL_DIR}` 即本 SKILL.md 所在目录（skill 启动时已给出 Base directory）。node 不可用或脚本报错时，按下方格式规范手动渲染兜底。

**格式规范**（脚本输出 = 此格式，手动兜底也按此）：**项目是顶级分类，但全表只用一张宽表**：项目列只在每组首行填写（视觉合并单元格效果），组内后续行该列留空；不为每个项目单独起表、组间不插空行，纵向零浪费。**跨多个项目的任务在每个相关项目组下各出现一行**（ID 后标 ⇄，分支列填该项目对应的分支）；无项目信息的任务归入「未关联」组。表前给一行全局总览。

```
任务 12 ｜ 🔄3 📋5 ✅4

| 项目 | ID | 任务 | 状态 | 优先级 | 进度 | 分支 |
|------|----|------|------|--------|------|------|
| **crestrail** | T-002 | Stripe 对接改工作流引擎 | 🔄 进行中 | 中 | 1/6 | feature/community-plugin-pay |
| | T-012 | 工作流画布右键菜单 | 📋 待开始 | 低 | 0/3 | feature/community-plugin-pay |
| **studio_web** | T-001 ⇄ | 支付中心交互样式优化 | 🔄 进行中 | 中 | 0/3 | feat/plugin-add-payment-center-20260605 |
| **shirehub-central** | T-001 ⇄ | 支付中心交互样式优化 | 🔄 进行中 | 中 | 0/3 | feat/community-add-plugin-payment-20260602 |
| **shirehub** | T-005 | 发帖 YouTube 链接解析 | 📋 待开始 | 中 | 6/8 | feat/create-post-iteration-20260527 |
```

规则：
- **项目组排序**：含进行中任务的项目在前，其余按组内最近更新降序；「未关联」永远最后
- **组内行排序**：进行中 → 停滞 → 待开始
- 分支列展示该任务在**当前项目**下对应的分支（同一任务在不同项目组下分支可不同）
- 进度列从"进度节点"中计算已勾选 / 总数

### git 状态扫描（scan.mjs）

**何时跑**：用户问"看任务/任务表/有啥在做/进度"时、或**会话开始**时，主流程先跑只读 `node "{SKILL_DIR}/scripts/scan.mjs"` 看真实 git 状态有无应归档 / reopen / 新候选；有应归档或 reopen 就 `--apply` 落地并告知用户，有新候选则询问用户是否建任务（拒绝则把 `仓库路径<TAB>分支名` 追加进 ignore.txt）：

```bash
node "{SKILL_DIR}/scripts/scan.mjs"            # 默认纯读取，只打印中文 markdown 报告（三段）
node "{SKILL_DIR}/scripts/scan.mjs" --apply    # 落地：已合并归档 + reopen 移回 active + 刷新进行中任务更新日期 + 清理超 30 天归档
```

脚本对每个 repo **动态识别主分支**（origin/HEAD → 本地 main/master，解析成本地 head 或 `origin/<名>` 真实 ref）与**集成/测试分支**（`{develop,dev,test,testing,staging,uat}` 里实际存在的），输出三段报告：

1. **✅ 检测到已合并、应归档的任务**：仅收"该任务全部分支都已合入**主分支**"的任务（部分合并单独提示、不自动归档，避免误删仍活跃的项目）。**只认主分支**——合入测试/集成分支不算完成。squash merge 祖先检测查不到——**查不到不当未合去打扰**，只报已确认合并的。
2. **🔄 检测到应重新打开（reopen）的归档任务**：扫 archive.md，对归档任务的每个 (repo, branch)，若该分支**仍存在**且**已不再是主分支的祖先**（即合并后又往这分支推了提交）→ 标记 reopen。归档那刻分支必然是主分支祖先，如今又领先只可能是合并后又改了，复用同一套祖先检测反过来用、无需额外状态。
3. **🌱 未跟踪的新分支候选**：在册 repo 里有提交、但 active.md 无对应任务的本地分支。过滤：跳过**主干集合**（动态识别的主分支 + 集成/测试分支 + `HEAD` 兜底）与 `release/*`；噪音阀门**三条全部满足**才算候选——`领先主分支 ≥2 提交` **且** `最近一次提交距今 ≤14 天` **且** `领先主分支 ≤50 提交`（0 提交、老死分支、长寿分叉分支一律出局）；命中 `~/.tasklog/ignore.txt` 的永久跳过。**候选只报告，绝不自动建任务。**

**主流程据报告动作**：
- 检测到已合并 → 跑 `--apply` 归档并告知用户"T-xxx 已合入主分支，已归档"。
- 检测到 reopen → 跑 `--apply` 把任务从 archive.md 移回 active.md（去完成行、状态置 🔄 进行中、迭代记录追加 `#### vN · 今日 · 合并后又改`、更新日期为今日），并告知用户"T-xxx 合并后又改，已重新打开"。
- 检测到新分支候选 → 像"被动建议建分支任务"那样询问用户要不要建任务；用户**拒绝**就把该 `仓库路径<TAB>分支名` 一行追加进 `~/.tasklog/ignore.txt`（永久不再提示）。

**忽略名单 `~/.tasklog/ignore.txt`**：每行一条 `仓库路径<TAB>分支名`（TAB 分隔），文件不存在视为空。作用是让用户明确拒绝过的分支不再被当作新候选反复打扰。

`--apply` 写 active.md/archive.md 是脚本自身的确定性操作（不走子代理，determinism 是设计核心）；而 ignore.txt 追加这类对话触发的写文件，沿用下方「子代理规范」派子代理写。

### 周回顾摘要

周回顾**优先从 archive.md 读最近完成的任务**（按 `完成` 日期筛近一周），git log 作为补充：对 active.md/archive.md 里出现过的各仓库执行 `git log --since="1 week ago" --oneline`（必要时加 `--author`），按仓库汇总一份完成清单。不生成周报正文，只给清单，写周报是用户自己的事。

## 子代理规范

以下操作统一走子代理（后台非阻塞）：

- 写/修改 `~/.tasklog/active.md`
- 完成归档：把任务块从 active.md 移入 `~/.tasklog/archive.md`（手动归档时）
- 追加 `~/.tasklog/ignore.txt`（用户拒绝某新分支候选时）
- git 分支合并检查

注：`scan.mjs --apply` 的归档写入由脚本自身完成（确定性操作，不走子代理）。

以下操作主流程直接执行（快，不需要后台）：

- 读 `~/.tasklog/active.md`（去重检查、渲染表格、周回顾）
- 解析自然语言、模糊匹配任务

子代理调用示例（Claude Code 环境）：

```
派子代理执行以下操作：
1. 读取 ~/.tasklog/active.md
2. {具体修改说明}
3. 写回文件
完成后无需回复。
```

其他 AI 环境（Cursor 等）：使用等效的后台任务或异步工具；若无法后台执行，则同步执行但告知用户"正在写入…"。

## 优先级推断规则

| 上下文信号 | 推断优先级 |
|-----------|----------|
| "领导说" / "老板要" / "今天必须" / "紧急" | 高 |
| "有空" / "顺便" / "不急" / "想做" | 低 |
| 无明确信号 | 中 |

## 注意事项

- **不提醒、不催促**：本 Skill 只做记录和查询，不主动推送任务提醒。
- **不写周报**：周回顾只给清单，周报正文由用户自己完成。
- **完成需有信号**：口头"完了"或检测到 push/merge 才触发完成流程；有分支信息时默认跑 git 核查，未合入**主分支**（每 repo 动态识别，合入测试/集成分支不算）会提示确认而非静默归档。完成的任务移入 archive.md 留档 30 天，不丢弃；若归档后该分支又领先主分支，下次 scan 会 reopen 它。
- **文件路径**：`~/.tasklog/` 在 Windows 上为 `%USERPROFILE%\.tasklog\`，在 macOS/Linux 上为 `~/.tasklog/`；同目录下含 `active.md`（活任务）、`archive.md`（归档）、`ignore.txt`（候选忽略名单）；子代理写文件时按当前平台处理路径。
- **render.mjs 向后兼容**：active.md 现已不含完成任务（完成即归档到 archive.md），render.mjs 渲染完成行的逻辑（`✅ ×N` 折叠 / `--all` 展开）因此基本不会命中，但保留不动以兼容历史数据。
