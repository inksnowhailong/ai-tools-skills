# 任务记录与追踪

将自然语言对话转换为结构化任务，存入单一文件 `~/.tasklog/active.md`。核心原则：**极低摩擦**——说话即记录，一句话即完成，不需要打开任何界面。

## 存储

唯一文件：`~/.tasklog/active.md`

- 无归档，git 即历史
- 完成任务标 ✅ 留在文件，用户决定何时清理
- 任务 ID 全局自增（T-001、T-002…），从文件里现有最大 ID + 1 计算

## active.md 格式

```markdown
# 任务清单

_最后更新：{日期}_

---

## T-001 · {任务标题}

- **状态**：{🔄 进行中 / 📋 待开始 / ✅ 完成 / 🕐 停滞}
- **优先级**：{高 / 中 / 低}
- **创建**：{YYYY-MM-DD}
- **更新**：{YYYY-MM-DD}
- **项目**：
  - `{仓库绝对路径}` — `{分支名}`

### 进度节点
- [x] {已完成子项}
- [ ] {待完成子项}

### 迭代记录
#### v1 · {YYYY-MM-DD} · {简述}
状态：✅ 完成 / 🔄 进行中
说明：{可选}

---
```

**停滞判断**：状态为"进行中"且距 **更新** 日期超过 5 天，显示 🕐 停滞。

## 触发识别

**优先判断意图，关键词只是辅助信号。** AI 应先判断用户是否在描述一件要做或已做的工作事项，再决定触发哪个操作——不要死扣关键词，也不要把日常口语（"我要做饭"）当任务。

| 信号 | 操作 |
|------|------|
| 明确指令："记录任务" / "新建任务" / "明确任务" | → 创建任务 |
| 口语描述工作事项："帮我记一下xxx" / "下午要改xxx" / "领导说要xxx" / "需要做xxx" | → 创建任务 |
| 列举多个待做事项（含编号、顿号、"第一/第二"、"三件事"等结构） | → 批量拆分 |
| "建个分支 feature/xxx" / "新建分支 xxx" / "checkout -b xxx" | → 被动建议创建任务 |
| **"xxx 完了" 且后面没有"但/还要/继续/不过"转折** | → 完成任务 |
| **"xxx 完了，但/还要/继续 yyy"（完成 + 转折）** | → 迭代追加（不标完成） |
| "T-xxx 继续" / "还要迭代" / "T-xxx 没完，还要..." | → 迭代追加 |
| "任务情况" / "看看任务" / "有啥在做" / "任务表" / "进度怎样" | → 渲染状态表 |
| "上周做了啥" / "这周完成了" / "帮我整理完成的任务" | → 周回顾摘要 |

**完成 vs 迭代追加的判断规则（最容易混淆）：**
- `"xxx 搞完了"` → 完成
- `"xxx 搞完了，还要加 yyy"` → **迭代追加**，同时把上一迭代标完成、追加新迭代块
- `"xxx 没完全完，还差 yyy"` → **仅追加进度节点**，状态不变

## 操作流程

### 创建任务

1. **去重检查**（主流程执行，不走子代理）：读 `~/.tasklog/active.md`，判断当前输入是否与已有进行中/待开始任务高度相似。
   高度相似的判断标准（同时满足）：
   - 功能描述重叠度高（同一功能模块或同一改动目标）
   - 涉及同一项目/仓库（或当前上下文一致）
   
   满足以上条件 → 列出候选，询问"是不是 T-xxx？"，用户确认后走迭代追加。
   仅功能名相似但项目不同，或相似度低 → 继续创建新任务，不打扰。

2. **解析任务**（主流程）：
   - 从自然语言提取：标题、优先级（从上下文推断，无法判断默认"中"）、涉及项目（若在对话或当前目录能识别）、分支（若提到）、子任务列表
   - 多任务输入（"三件事：xxx / yyy / zzz"）→ 逐条生成多个任务块

3. **派子代理写文件**：
   - 读当前 `~/.tasklog/active.md`（不存在则创建）
   - 计算下一个 ID
   - 在文件末尾追加任务块
   - 更新 `_最后更新_` 日期

4. **主流程返回**：告知用户已建立 T-xxx，不等子代理完成后再响应。

### 被动建议（分支创建）

检测到用户提及新建 git 分支时，**不强制创建**，主动询问：

```
检测到你提到新建分支 feature/xxx，要为它建个任务吗？（不建直接忽略）
```

用户确认才走创建流程。

### 完成任务

1. **先判断是否含转折**：输入中有"但/还要/继续/不过/就是还差"等转折词 → 走**迭代追加**，不走完成。

2. **匹配规则（按优先级）**：
   - 输入含 `T-xxx` 格式 ID → 直接命中，无需确认
   - 输入含任务标题关键词 → 在**进行中/待开始**任务里模糊匹配
     - 唯一匹配 → 直接标完成
     - 多个候选 → 列出让用户选，不要猜
     - 完全匹配不到 → 告知用户没找到相关进行中任务，询问是否要新建

3. 派子代理：
   - 把对应任务状态改为 `✅ 完成`，更新 `更新` 日期
   - 若有迭代记录，最新一条迭代状态也标完成
4. **可选 git 核查**（用户说"帮我查一下是不是真合进去了"时触发，不默认执行）：
   - 子代理对任务 `项目` 数组里每个仓库执行：
     ```bash
     cd {仓库路径} && git branch --merged master | grep {分支名}
     ```
   - 跨分支链（feature→dev→master）：若直查不到，检查 dev 是否已 merge 进 master：
     ```bash
     git log master --merges --oneline | grep -i "merge.*dev\|dev.*merge"
     git branch --merged master | grep dev
     ```
   - 查到合并 → 补充确认已完成；查不到 → 提示分支尚未落地 master

### 追加迭代（不新建任务）

1. 定位到已有任务（ID 或模糊匹配，规则同完成任务）
2. 派子代理（以下为原子操作，一次完成）：
   - 若有迭代记录且最新一条状态为"进行中" → **先把该条改为 ✅ 完成**
   - 在 `迭代记录` 末尾追加新版本块：
     ```markdown
     #### v{n} · {今日} · {本次迭代简述}
     状态：🔄 进行中
     说明：{用户说的新需求}
     ```
   - 任务整体状态改回 `🔄 进行中`
   - 更新 `更新` 日期
3. 主流程告知用户：T-xxx 已追加 v{n} 迭代，继续进行中。

### 渲染状态表

主流程直接读 `~/.tasklog/active.md` 并渲染，不走子代理：

```
| ID    | 任务              | 状态       | 优先级 | 进度   | 项目                |
|-------|-------------------|------------|--------|--------|---------------------|
| T-003 | 数据导出功能      | 🔄 进行中  | 高     | 2/5    | app, backend        |
| T-004 | 首页重构          | 🕐 停滞    | 中     | 1/3    | app                 |
| T-001 | 用户登录          | ✅ 完成    | 高     | 5/5    | app                 |
```

排序：进行中 → 停滞 → 待开始 → 完成。进度列从"进度节点"中计算已勾选 / 总数。

### 周回顾摘要

主流程直接读 active.md，过滤出 `✅ 完成` 的任务，生成列表：

```
本周完成任务（供周报参考）：
- T-001 · 用户登录模块（高优，涉及 app/backend，共 3 个迭代）
- T-002 · 首页重构（中优，涉及 app）
```

不生成周报正文，只给清单，写周报是用户自己的事。

## 子代理规范

以下操作统一走子代理（后台非阻塞）：

- 写/修改 `~/.tasklog/active.md`
- git 分支合并检查

以下操作主流程直接执行（快，不需要后台）：

- 读 `~/.tasklog/active.md`（去重检查、渲染表格、周回顾）
- 解析自然语言、模糊匹配任务

子代理调用示例（Claude Code 环境）：

```
派子代理执行以下操作：
1. 读取 ~/.tasklog/active.md
2. {具体修改说明}
3. 写回文件
完成后无需回复。
```

其他 AI 环境（Cursor 等）：使用等效的后台任务或异步工具；若无法后台执行，则同步执行但告知用户"正在写入…"。

## 优先级推断规则

| 上下文信号 | 推断优先级 |
|-----------|----------|
| "领导说" / "老板要" / "今天必须" / "紧急" | 高 |
| "有空" / "顺便" / "不急" / "想做" | 低 |
| 无明确信号 | 中 |

## 注意事项

- **不提醒、不催促**：本 Skill 只做记录和查询，不主动推送任务提醒。
- **不写周报**：周回顾只给清单，周报正文由用户自己完成。
- **不自动完成**：口头"完了"才标完成，git 检查是可选的辅助确认，不是自动触发。
- **文件路径**：`~/.tasklog/` 在 Windows 上为 `%USERPROFILE%\.tasklog\`，在 macOS/Linux 上为 `~/.tasklog/`；子代理写文件时按当前平台处理路径。
